# 03 — 剧情树规范

## 核心概念：树 + 引用

剧情结构是**一棵树**：L1 是根，向下展开 L2 → L3 → L4。不同层级的节点分目录存储只是为了查看方便，**父子关系才是结构本身**。

**L4 正文与 L3 事件不是一对一**：
- **一个事件写多章**：一个 L3 可以挂多个 L4 子节点
- **一章写多个事件**：一个 L4 挂在它的"主事件"L3 下（树），还可以**引用其他 L3 事件**（切换视角、倒叙、多线并进）——引用关系存入数据库 `references` 表（kind=main|secondary），从 L3 反向查所有关联 L4 只查这一张表

确认规则（数据层强制，见"状态与确认"）：
- 任何节点的创建、确认都以**父节点已确认**为前提；L4 引用的所有 L3（主+次）也必须已确认
- 建议整体按 L1 → L2 → L3 → L4 推进，但**允许部分推进**：任一节点确认后即可开始创建它的子节点，不必等同级全部完成。L1 是唯一的根，必须先创建并确认
- 任何节点内容被修改后，后续节点会被自动标记为 `affected`（待核查），见下

## 数据存储（三个库）

库拆分：素材与节点分离，风格独立（跨项目可搬）。

```
novel-cli/nodes.db      剧情树 plot_nodes + 引用 references + 事实 facts/fact_consumption
novel-cli/materials.db  素材库 entries + dimensions + types（类型字典）
novel-cli/style.db      工作区风格库（引例 + 特征规则）；根目录 style.db 为参考库
```

## 分卷存储（L3 / L4）

L3 和 L4 节点数量多，**按卷分目录存储**：

```
plots/L3/1/1_事件名.md        # 第 1 卷的事件，文件名 = 排序_标题
plots/L3/2/2_事件名.md        # 第 2 卷
plots/L4/2/1_章节名.md        # 第 2 卷的正文
```

- 卷目录号 = `volume_num`，即**排序号（1, 2, 3…）**，创建 L3/L4 时自动继承父节点的卷号
- 文件名 = `{排序}_{标题}.md`（下划线分隔）
- **L4 的排序（sort）同卷内必须唯一**（数据层校验）——它是卷内章序的依据
- **"序卷"/"第零卷"不占用特殊卷号**：卷的地位在 L2 分卷梗概的卷名处写明（如"序卷-阿利斯戴尔"），卷号仍然从 1 开始按排序

L1（仅一个）和 L2（每卷一个节点）直接存在层级目录下：`plots/L1/全书梗概.md`、`plots/L2/第一卷-无痕者.md`。

## 层级定义

| 层级 | 名称 | 内容 | 存储 |
|---|---|---|---|
| L1 | 全书梗概 | 全书方向：核心冲突、主线弧光、主要角色、世界观关键设定、分卷规划 | `plots/L1/` |
| L2 | 分卷梗概 | 每卷的主旨、卷首语、结语、角色发展、关键事件清单、情感曲线 | `plots/L2/` |
| L3 | 事件梗概 | 单个事件的**完整设计**——设计到"填入具体描写即成正文"的程度 | `plots/L3/{卷}/` |
| L4 | 正文 | 正式章节文本（agent 缓存工作区，确认后 `publish` 到 `contents/`） | `plots/L4/{卷}/` |

> **设定集不在梗概里**。所有设定（角色、地点、道具、概念、场景模型、伏笔）写入素材库数据库（见 guide 02），梗概只描述"故事怎么走"，不承载设定。

## L1 — 全书梗概

**内容模板**：
```markdown
# 全书概要

## 核心冲突
[一句话概括全书核心矛盾]

## 主线弧光
[主角从 A 状态 → B 状态的完整变化轨迹]

## 主要角色
- **[角色名]**：[一句话定位 + 在主线中的角色]

## 世界观关键设定
- **[设定名]**：[一句话说明]

## 分卷规划（初步）
- 第一卷：[主题/目标]
- 第二卷：[主题/目标]
```

**确认要求**：用户明确认可全书方向后才能创建 L2。

## L2 — 分卷梗概

**一个 L2 节点 = 一卷**。每一卷必须有**明确的主旨**，并配**卷首语**和**结语**。卷的特殊地位（序卷/第零卷/正卷）在卷名处写明，例如"序卷-阿利斯戴尔"，卷号仍按排序。

**内容模板**：
```markdown
# 第X卷：[卷名]

## 本卷主旨
[一句话：本卷在全书主线中的核心命题/作用]

## 卷首语
[本卷开篇定调的话，可直接用作卷首]

## 结语
[本卷收束的话，可直接用作卷尾]

## 角色发展
- **[角色名]**：[本卷内的变化/揭示]

## 关键事件清单
1. [事件简述] — 作用：[推动主线/揭示设定/角色发展]

## 情感曲线
[本卷情感张力走向：开端→发展→高潮→收束]
```

**确认要求**：本卷确认后即可创建该卷的 L3（允许部分卷先行，不必等所有卷完成）。

## L3 — 事件梗概

**L3 事件与 L4 正文不是一对一**：
- 一个事件可以写多章（一个 L3 挂多个 L4 子节点）
- 一章可以写多个事件（L4 的主引用 + 次引用都存入 `references` 表）
- 写作 L4 时，**主事件和被引用的所有事件都必须是 confirmed**（数据层强制）

**L3 的要求**：把事件的整个过程设计好，达到"填入具体描写就能成为正文"的详细度。模板：

```markdown
# 事件 [编号]：[事件名]

## 基本信息
- **所属卷**：第X卷
- **地点**：[从素材库核实]
- **参与角色**：[从素材库核实]
- **时间跨度**：[事件发生的时间范围]

## 事件目的
[本事件在剧情链条中的功能：埋设/揭示什么、角色如何变化、推动什么]

## 场景序列
[按发生顺序列出每个场景；本章有多线时注明切换与视角]

### 场景 1：[场景名]
- **地点/时间/在场人物/视角**：[...]
- **动作节拍**：[按顺序细化到可执行，填入描写即成正文]
- **对话要点**：[关键台词与意图；不必成文，但要点齐全]
- **信息揭示/伏笔**：[本场景释放或埋设什么]

### 场景 2：[场景名]
...

## 情感弧线
[本事件情绪变化：起始→转折→结束]

## 悬念与衔接
[结束时留下的钩子；与前后事件的衔接点]

## 涉及设定
- 角色：[列出需 `entry get` 核查的角色]
- 地点：[列出需核查的地点]
- 道具/概念：[列出]
- 场景模型/伏笔：[如涉及反复出现的场景或已埋伏笔，列出]
```

**写前**：先运行 `context <id>` 组装上下文（父链/被引用情况/事实账本/风格规则），再按"涉及设定"逐条 `entry get`。

**确认要求**：事件确认后可创建其 L4。

## L4 — 正文

**输出位置**：`novel-cli/plots/L4/{卷}/{排序}_{章节名}.md`——agent 的缓存工作区，按卷分目录，**排序同卷内唯一**（卷内章序）。

**内容模板**（★ md 只写正文——主事件/引用事件/素材等元数据存入数据库，由 `context` 命令组装，**不写入正文文件**，保证发布产出干净）：
```markdown
# [章标题]

（正文）
```

**写作前的元数据来源（全部在数据库，不落正文文件）**：
- 主事件 / 引用事件 → `plot ref list <id>`（references 表）
- 涉及素材（角色/地点/场景模型/伏笔）→ 按 L3 模板"涉及设定"逐条 `entry get`
- 事实账本 / 风格规则 / 前后章 → `context <id>` 一键组装

**写前检查**：
- [ ] 已运行 `context <id>`：父链/引用事件/事实账本（勿重复写出）/风格规则（KEEP 做 WEAKEN 避）/前后章
- [ ] 主事件与被引用的所有 L3 均为 confirmed（否则会被数据层拒绝）
- [ ] 已按涉及设定 `entry get` 核查角色/地点/场景模型/伏笔
- [ ] 已读取前一个同级 L4 的结尾（衔接）与下一个节点规划（下章前瞻）

**写后**：
1. 文中产生的新设定 → `entry set` / `entry append` 回填素材库；伏笔状态 open/resolved 更新
2. 执行去 AI 味清单 + 风格自查（见 guides/07、04）
3. 用户确认正文 → `plot status confirmed` → `publish`

## 发布（publish）

输出到 `contents/{卷}/`，文件名 = **`{全书章号}_{卷内章号}_{标题}.txt`**：

```
contents/3/98_5_第三卷第五章标题.txt
```

- 卷内章号 = 同卷内按 L4 排序（sort）排序的序号；全书章号跨卷累计
- 例：第三卷第五章（全书第九十八章）→ `contents/3/98_5_xxx.txt`
- **文本替换**：发布时 `{{key}}` 占位符按 translation 表替换为最终名（写作规范见 guides/02"名称映射"）；未登记的 `{{...}}` 保留并提示

## 事实账本（facts）

每个节点确认/发布后记一条"已完成事项"（`fact add`，含 `--source` 来源节点），写作前 `fact list` 查看"勿重复写出"。改动级联的第二跳：改某节点 → `fact list --source <id>` 找到它确认过的事实 → `fact_consumption` 查到消费这些事实的节点。详见 guides/04。

## 状态与确认（数据层强制）

**状态枚举**：

| 状态 | 含义 |
|---|---|
| `draft` | 未确认 |
| `confirmed` | 已确认 |
| `revised` | 内容被修改，需要重新确认 |
| `affected` | **未被直接修改，但因前置内容变化需要核查衔接**——只能由级联自动产生，不能手动设置 |
| `published` | 已发布到 `contents/` |

**确认链路**：任何节点置 `confirmed` 的前提是**整条祖先链（到 L1）都 confirmed**，否则数据层拒绝，并报出具体未确认的祖先。

**级联规则**（某节点被置 `revised` 时自动触发，沿树与引用网络闭包传播）：
1. 树传播：该节点的**全部子树**（任意深度）→ `affected`
2. 树传播：该节点**同父的后续同级**（sort 更大）及其子树 → `affected`
3. **引用网络闭包**：该节点若为 L3 → 引用它的所有 L4 → 这些 L4 引用的其他 L3 → 再波及那些 L3 的 L4……**直到闭包稳定**（沿 `references` 表双向 BFS）
4. 已 `published` 的节点同样会被标 `affected`（`contents/` 文件不动，只提醒"可能过时"）
5. `affected` 节点核查后重新置 `confirmed`（祖先链确认时允许）即恢复

**长期提醒**：`plot list` / `novel_status` 每次运行都会列出所有 `affected` 节点及其原因（`affected_reason`），直到重新确认。这是**持续有效**的核查提示——可能经历多轮修改后才轮到重写衔接，这期间提醒一直在。

## CLI 命令

### 创建剧情节点
```bash
python novel-cli/cli.py plot create L1 "全书概要"
python novel-cli/cli.py plot create L2 "序卷-阿利斯戴尔" --parent 1 --volume 1 --sort 1
python novel-cli/cli.py plot create L2 "第一卷-无痕者" --parent 1 --volume 2 --sort 2
python novel-cli/cli.py plot create L3 "1-1-客栈的清晨" --parent 3 --sort 1   # 卷号自动继承
python novel-cli/cli.py plot create L4 "1-1-客栈的清晨" --parent 5 --sort 1   # sort 同卷唯一
```

### 引用关系（references）
```bash
python novel-cli/cli.py plot ref add 7 4      # L4 #7 添加对 L3 #4 的次引用（被引用事件须已确认）
python novel-cli/cli.py plot ref list 7       # 列出节点引用（→ 正向 / ← 反向）
python novel-cli/cli.py plot ref del 7 4      # 删除次引用（主引用与树绑定，不可删）
```

### 事实账本与上下文
```bash
python novel-cli/cli.py fact add "第5章完成：林夜得知星核存在" --category revealed --source 5
python novel-cli/cli.py fact list [--category X] [--source id]
python novel-cli/cli.py context 7              # ★ 写作前组装上下文（引用/事实/风格规则/前后章）
```

### 查看和列表
```bash
python novel-cli/cli.py plot get 3              # 节点详情+内容（含状态与 affected_reason）
python novel-cli/cli.py plot list [--level L3]  # 列出节点（affected 有 ⚠ 标记）
```

### 更新状态
```bash
python novel-cli/cli.py plot status 3 confirmed   # 确认（祖先链校验）
python novel-cli/cli.py plot status 3 revised     # 标记修改（触发树+引用网络闭包级联）
# affected 不可手动设置
```

### 发布正文
```bash
python novel-cli/cli.py publish 3
```
自动：读取 md → 转纯文本 → 计算卷内章号与全书章号（按 L4 排序）→ 写入 `contents/{卷}/{全书章号}_{卷内章号}_{标题}.txt`
